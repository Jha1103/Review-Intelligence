# Milestone 5 — AI Product Feedback Intelligence and Support Automation
## Project Plan (n8n-first architecture)

### 1. Objective
Convert **8–12 weeks of public Groww app reviews** into four demonstrable outputs:

1. **AI review intelligence report** — up to 5 themes, top-3 ranked by programmatically calculated frequency, exactly 3 verbatim quotes with real review IDs.
2. **Weekly internal product pulse** — top themes, 3 quotes, key observation, exactly 3 suggested product actions, **maximum 250 words**.
3. **Verified customer support fee explainer** — derived only from a detected recurring fee issue, **maximum 6 neutral factual bullets**, **2 real official product URLs**, `Last checked: [verified date]`.
4. **Approval-gated MCP workflow** — after an explicit Approve decision only, appends a structured dated entry to an existing Google Doc and creates a **Gmail draft (never sends)**.

### 3. Architecture (n8n-first)
Python is used **only** for data collection, cleaning, and local validation/testing. n8n Cloud + Gemini handle AI review intelligence, report generation, human approval, and MCP publishing.

| Layer | Responsibility | Runs where |
|-------|---------------|------------|
| Data Layer | Scrape public Groww reviews (8–12 wk window), clean/dedupe/filter, export CSV, load to Google Sheets | Python + Pandas (local) → Google Sheets |
| AI Intelligence Layer | Read Sheets; Gemini discovers ≤5 themes, classifies reviews, extracts 3 verbatim quotes, detects recurring fee issue | n8n Cloud + Gemini |
| Deterministic validation | Code nodes calculate frequencies, validate evidence, enforce formatting rules | n8n Code nodes |
| Output Layer | Generate ≤250-word pulse and ≤6-bullet fee explainer | n8n + Gemini |
| Human Approval | n8n form displays BOTH complete outputs; explicit Approve/Reject; Reject = zero external writes | n8n Cloud form |
| MCP Layer | After approval only: `append_to_doc` (Google Doc) and `create_email_draft` (Gmail draft, never send) | n8n MCP Client → MCP Server Trigger |
| Persistence | Run IDs, approval decisions, payload hashes, action status in n8n-accessible store (Data Tables or Google Sheets) | n8n Cloud |

### 6. Success criteria
- All reviews carry original review ID, date, rating, source provenance, and exact original text.
- Max 5 themes; top 3 ranked by programmatic frequency; exactly 3 verbatim quotes with real review IDs.
- Fee issue proceeds only if supported by multiple actual reviews; otherwise stop + manual review.
- Pulse ≤250 words; fee explainer ≤6 bullets with 2 real official URLs and verified "Last checked" date.
- Deterministic validation passes on formats, sources, quotes, evidence, PII, word limits.
- No Google Doc append or Gmail draft without explicit Approve; run state persisted in n8n-accessible store.
- No credentials committed; no invented data, URLs, screenshots, or execution results.

### 7. Risks & assumptions
- `google-play-scraper` availability and review coverage for Groww are external dependencies.
- Gemini API access and n8n Cloud credentials must be provided by the user (never hardcoded).
- The target Google Doc must already exist and be shared with the n8n connector (integration phase).
- The Gemini model used must be verified as supported before implementation.
- Product is confirmed as Groww; no further product confirmation needed.

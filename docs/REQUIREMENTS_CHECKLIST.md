# Milestone 5 — Requirements Checklist (A–L) (n8n-first)

Status key: `Planned` / `Implemented` / `Verified`.

| ID | Requirement | How it is satisfied (n8n-first) | Verification | Status |
|----|-------------|---------------------------------|--------------|--------|
| A | Collect genuine public reviews within a configurable recent 8–12-week window. Preserve original review IDs, dates, ratings, source references, and review text. | `src/collect_reviews.py` uses `google-play-scraper` for Groww (`com.nextbillion.groww`, `in`, `en`) with a configurable `WEEKS_BACK` window (default 12). Preserves `reviewId`, `at`→`review_date`, `score`→`rating`, `content`→`review_text`, source URL/provenance. | Unit test asserts all five fields present and non-null for every row; window bounds checked against `review_date`. | Implemented |
| B | Deduplicate, clean, document exclusions, and preserve evidence. | `src/clean_reviews.py` deduplicates by `reviewId`, drops empty/invalid reviews, redacts PII, writes `data_quality_report.json` with counts and exclusion reasons (no PII in log). | Deterministic test: no duplicate `reviewId` in `cleaned_reviews.csv`; quality report has fetched/date-filtered/duplicate/excluded/cleaned counts. | Implemented |
| C | Discover max 5 themes. Rank top 3 using programmatically calculated frequencies. Extract exactly 3 verbatim quotes with real review IDs. | n8n + Gemini discovers ≤5 themes; n8n Code nodes compute frequencies with JavaScript; top-3 ranked; exactly 3 verbatim quotes each bound to a real `reviewId`. Python + Pandas are for local data processing only. | Assert ≤5 themes; top-3 order matches computed frequency; each quote string appears verbatim in a review row and quote→reviewId mapping resolves. | Planned |
| D | Identify a recurring fee issue supported by multiple actual reviews. Never invent. If none, stop and request manual review. | n8n + Gemini detects fee issue only when ≥2 cleaned reviews support it. Otherwise workflow stops and requests manual review; no fee facts emitted. | Test with fee-free data → branch stops. Test with multi-review fee evidence → proceeds. | Planned |
| E | Structured weekly product pulse: top themes, 3 quotes, key observation, exactly 3 suggested product actions, max 250 words. | n8n + Gemini assembles pulse; n8n Code nodes count words (≤250) and assert exactly 3 actions. | Word-count test ≤250; assert exactly 3 "Action:" items; assert 3 quotes present. | Planned |
| F | Fee explanation from detected issue: max 6 neutral factual bullets, 2 real official product URLs, Last checked: [verified date]. No invented facts/URLs. | n8n + Gemini derives bullets only from detected reviews; URLs from verified official sources (pricing, support); `Last checked:` set to actual verification date. URLs are not required before fee issue is identified. | Assert ≤6 bullets; both URLs match official sources; `Last checked:` present and parseable as a date. | Planned |
| G | Validate output formats, source references, quote accuracy, issue evidence, PII handling, and word limits using deterministic checks. | n8n Code nodes run all checks; local `tests/` validate dates, dedup, content preservation, PII redaction. | `pytest tests/` passes on clean sample; fails on injected violations (duplicate quote, missing URL, PII present, >250 words). | Implemented |
| H | Display both outputs before allowing an explicit Approve/Reject decision. | n8n CE Wait form displays both complete outputs (pulse + fee explainer); user makes explicit Approve/Reject. No local CLI approval in final workflow. | Workflow JSON exported with Wait form + If node; Reject branch has no outgoing connection. | Implemented |
| I | After approval only, use a real n8n MCP Client Tool to invoke MCP Server Trigger tools named `append_to_doc` and `create_email_draft`. | n8n CE workflow uses MCP Client Tool to call those two named MCP Server Trigger tools, gated on approval state. | Workflow JSON exported; MCP Client node present; no AI Agent toolWorkflow pattern. | Implemented |
| J | After approval only: append structured dated entry to existing Google Doc; create Gmail draft with both outputs; never send. | `append_to_doc` writes runId, date, pulse + fee summary to the doc; `create_email_draft` creates draft only. | Delivery workflow JSON exported with Google Docs + Gmail nodes; no "send" email node. | Implemented |
| K | Prevent unapproved actions and reduce duplicate writes with persisted run ID, approval state, and action status. | Approval/audit record keyed by run_id + SHA-256 payload hash stored in Google Sheets approval_log. Delivery workflow independently verifies before any write; per-action status tracking prevents duplicates. | Workflow JSON exported; Compute Approval Record Code node + Verify Authorization Code node present. | Implemented |
| L | Produce README, source list (4–6 URLs), sample reviews CSV, Markdown pulse, fee explainer, workflow exports, screenshots, 3-minute demo script. | Shipped: `README.md`, `sources.md` (4–6 official URLs), `data/reviews_sample.csv`, `outputs/pulse.md`, `outputs/fee_explainer.md`, `n8n/Groww - Full 1000 Review Analysis.json`, `n8n/Groww - Delivery Actions.json`, `screenshots/`, `demo_script.md`. | File-existence test; both workflow JSONs valid; `sources.md` has 4–6 URLs. | Implemented |
| M | Phase 3.2: Fixed taxonomy of ≤5 themes with strict descriptions and assignment criteria. | `src/taxonomy.py` defines T1-T5 with descriptions, criteria, examples, counter-examples. | Unit test asserts exactly 5 themes, valid structure. | Implemented |
| N | Phase 3.2: Deterministic batch generation of 25 reviews/batch, max 4 batches (100 reviews) for initial test. | `src/batch_generator.py` deterministic systematic sampling (seed=42, offset=2, step=10); no duplicates; no first-100-alphabetically selection. | Unit test asserts no duplicate review IDs across batches, correct batch sizes, reproducibility, not-first-100-alphabetically. | Implemented |
| O | Phase 3.2: Deterministic JavaScript validation per batch — every input classified once, no unknown/duplicate IDs, valid themes/sentiments/fee topics, correct counts, questionable fee-subtype flagged. | `src/batch_validator.py` (Python reference) + n8n Code node JavaScript. Validates `content.parts[0].text` parsing. | Unit tests for missing/duplicate/unknown IDs, invalid themes/sentiments/fee topics, fee-topic consistency, empty themes for unclear reviews. | Implemented |
| P | Phase 3.2: Theme frequency aggregation through JavaScript, one review at most once per theme, distinguishes pilot/initial-test/final counts. | `src/batch_validator.py` `aggregate_theme_frequencies()` + n8n Code node. Requires exactly 100 unique reviews; fails on duplicates/missing. | Unit test asserts correct theme counts, scope labels distinguish counts, fails on ≠100 unique reviews. | Implemented |
| Q | Phase 3.2: Privacy protection — sanitized text only in prompts, redacted reviews not eligible for verbatim quotes. | `cleaned_review_text` only sent to Gemini; `quote_eligible=no` reviews classified but not quoted; `original_review_text` never in Google Sheets. | Unit test asserts quote_eligible preserved, no original_text in exports, PII flags preserved. | Implemented |
| R | MCP delivery: Authorization verification (run_id + SHA-256 payload hash) in delivery workflow before any external write. Duplicate-write prevention per run_id + operation. | Delivery workflow Verify Authorization Code node checks run_id + payload_hash against approval_log; per-action status tracking prevents duplicates. | Workflow JSON exported; authorization Code node present; all paths route through authorization. | Implemented |
